# Web grounding in 2.1.0-beta3

The previous web feed returned dictionary/currency pages for “Who won the 2026 Nobel Prize in Physics?” and calendar pages for year-first searches. BI could pass irrelevant pages to the model. Only the first three links were tried, useful short headings were discarded, and all source excerpts were shrunk equally when context was tight. A failed live search still allowed a model-only answer.

## Updated behaviour

- A deterministic query plan removes question boilerplate, retains topic/year terms, and resolves relative-year queries using the device date. It preserves Unicode combining marks. Bing's public news and web feeds are compared concurrently, with stronger topic matches read first. The news feed wins ties for recent/year-sensitive questions; the web feed wins other ties. A long list of weak web matches cannot suppress more relevant news pages. No key, cloud model or private chat history is used.
- Search titles are screened for topic/year relevance and obvious prediction headlines. News tracking URLs are decoded to their HTTPS publisher targets without requesting the HTTP tracking endpoint. Publisher pages must themselves match the topic and requested year. Explicit public links remain directly readable.
- Up to six distinct publisher hosts are tried, three concurrently. Each search feed gets six seconds, each page read eight seconds, and the coordinator has a thirty-second overall limit. HTML parsing runs on IO workers. The existing 1 MiB response limit, cancellation, public-only DNS checks, HTTPS redirect checks and credential guard remain active.
- At most three readable sources are retained. Query-relevant sentences and short headings are preserved first. Publication/update metadata is extracted before removing scripts, and page-reported versus search-reported dates are labelled separately. Retrieval time is not presented as publication time. Relative “latest/current” searches require evidence dated within thirty days; “today” requires today's reported date. This deliberately prefers an unavailable answer to stale evidence.
- Prompt preparation drops lower-ranked sources before shrinking all excerpts into fragments. Only sources actually included in the model prompt are saved as that answer's source cards. The local model is instructed to copy names/numbers/years accurately, cite source IDs and decline unsupported facts. This does not constitute automatic semantic fact verification.
- Small models can omit inline markers: the app retains the read source cards and labels the answer `CITATIONS_MISSING` rather than adding invented markers or claiming that the answer was verified. Output containing only citation markers is replaced with an unavailable response. Tests distinguish factual correctness, available evidence and valid marker syntax.
- When an enabled web request fails or finds no relevant pages, chat saves a deterministic unavailable response with `INSUFFICIENT_EVIDENCE` and generates no model tokens. Legacy saved model-only failure labels remain readable. Web-off and credential-blocked local requests retain their existing behaviour. Binder/TypeRight requests do not invoke research.

## Independent reference facts for live testing

On 21 October 2026, [CERN's 6 October announcement](https://home.cern/cern-congratulates-nobel-prize-winner-francis-halzen/) and [IceCube's announcement](https://icecube.wisc.edu/news/awards/2026/10/francis-halzen-icecube-principal-investigator-wins-2026-physics-nobel-prize/) identify Francis Halzen as the 2026 physics laureate. [The Royal Swedish Academy of Sciences' 7 October release](https://www.kva.se/en/news/the-nobel-prize-in-chemistry-2026/) identifies Henri B. Kagan and Kenso Soai as the chemistry laureates. These reference names exist only in the opt-in test fixture, not in runtime search or answer code.

The opt-in `GroundingRecentAnswerDeviceTest` exercises the actual chat ViewModel, live website retrieval, persisted source cards and an Apache-2.0 Qwen 2.5 0.5B GGUF on CPU in the isolated validation package. It records the installed app version and tests both discovered news questions and a directly supplied public page. The improved phase also checks that an inaccessible private URL produces an honest refusal with zero generated tokens.

Public feeds and publisher HTML can change, block automation or omit reliable dates. Some relevant pages may be rejected by the conservative topic/date checks. A citation establishes where retrieved text came from; it does not prove every generated statement or a publisher's accuracy. The user should inspect sources for important decisions.

Generation settings now retain the requested CPU thread count across preference emissions, including conversation and appearance changes. Previously those emissions reconstructed parameters with automatic threads and discarded saved benchmark recommendations. Zero remains automatic; positive settings are capped at eight in storage and remain bounded by device cores, power and thermal policy at inference time.
